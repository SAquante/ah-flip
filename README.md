# AH Флип — аукцион WoW Forever на Android

Приложение для аукциона `bootybaybroker.com` (WoW Forever, EU / EU PvE / Альянс по умолчанию).
Считает, что выгодно купить и сдать НПС, что выгодно распылить и что выгодно скрафтить,
и отдаёт это списками с суммами в золоте.

## Экраны

| Вкладка | Что показывает |
|---|---|
| **Обзор** | Состояние рынка, суммарный потенциал, топ-3 по каждому разделу |
| **Аук** | Полный аукцион: поиск по названию, категории и подкатегории, качество, сортировка, страницы |
| **Флипы** | Лоты дешевле цены НПС + скидки под рынком (перепродажа с учётом комиссии 5%). Сверху — возраст скана и кнопка **⟳ Обновить** |
| **Распыл** | Купить зелёный/синий предмет → распылить → продать материалы; ROI и состав дропа |
| **Крафт** | Рецепты по профессиям, себестоимость, прибыль, продажи в день |
| **Стата** | Движения рынка за 7 дней и сводка по миру |
| **Поиск** | Быстрая проверка одного предмета: аукцион / рынок / цена НПС |

Настройки (⚙): регион EU/US, игровой мир, фракция, профессия, порог скидки.

## Скорость и кэш

Полное обновление занимает 3–4 минуты: каждый запрос требует свежей страницы в WebView
(см. ниже), а их около восьми. Поэтому последний удачный скан кладётся в `cacheDir`:

- при запуске данные показываются **сразу** (≈5 секунд) с честной подписью «Обновлено: N мин назад»;
- обновление идёт в фоне, экран не блокируется — внизу висит тонкая полоска «Обновляю…»;
- кнопка **⟳ Обновить** на экране «Флипы» и ⟳ в нижней панели запускают то же обновление вручную.

Первый запуск после установки (кэша нет) показывает полноэкранную загрузку.

## Как это получает данные

Сайт закрыт Cloudflare managed challenge и проверяет TLS-отпечаток, поэтому обычный HTTP-клиент
получает 403 даже с cookie `cf_clearance`. Приложение держит маленький видимый `WebView`,
который один раз проходит проверку, и дальше выполняет запросы как `fetch()` из самой страницы.

Особенности WebView, из-за которых транспорт выглядит именно так:

- тело больше ~40 КБ не доходит до Java одним вызовом — ответ отдаётся кусками через JS-мост;
- JS-контекст страницы живёт один запрос, поэтому перед каждым запросом страница перезагружается
  (cookie сохраняются, проверка заново не решается);
- сервис-воркер SPA перехватывает `/api/`, поэтому бандлы `/assets/` не загружаются.

Ответы API читаются как есть: комиссия аукциона, «продаж в день», ROI и цены НПС уже посчитаны
сайтом — приложение их не дублирует, а только раскладывает по спискам и сортирует.

## Русские названия

API сайта отдаёт английские названия предметов (кроме поисковых подсказок). Русские имена
подтягиваются из публичного тултип-API Wowhead по id предмета и кешируются в `SharedPreferences`,
поэтому каждый предмет переводится один раз. Пока имя не пришло, показывается английское —
именно его клиент игры и показывает на этом сервере.

**Предметы, которых нет ни в одной базе** (придуманные этим сервером, id в районе 28xxxx —
например `Robes of the Blind Cultist`), не переводятся ничем: сайт сам отдаёт для них
`localizedName: null`. Такие позиции остаются на английском, как и в клиенте игры.

Категории и подкатегории («Броня», «Ткань», «Расходники», «Сумка для реагентов») переводятся
локальной таблицей в `CategoryRu`. Служебные коды (`verdict: "current"`) показываются как
«актуален».

## Сборка

```powershell
$env:JAVA_HOME="C:\tools\jdk-21.0.12.1+1"
$env:ANDROID_HOME="...\iptv-tv\_tools\android-sdk"
...\iptv-tv\_tools\gradle-8.11.1\bin\gradle.bat :app:assembleRelease
adb install -r app\build\outputs\apk\release\app-release.apk
```

Тесты (парсинг ответов и форматирование денег):

```powershell
...\gradle.bat :app:testReleaseUnitTest
```

## Файлы

- `Api.kt` — модели ответов, конструкторы URL, список профессий
- `SiteClient.kt` — WebView-транспорт с обходом Cloudflare
- `AppViewModel.kt` — загрузка, кеш состояния, фильтры
- `RuNames.kt` — русские названия предметов
- `Screens.kt`, `AuctionScreen.kt` — экраны
- `Money.kt` — формат «1г 23с 45м»
